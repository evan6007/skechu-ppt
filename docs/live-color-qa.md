# 即時調色與編輯效能（v96）

## 行為

- 線條、箭頭、文字、圖形填色／外框、標籤及漸層色標在 `input` 時更新，不等關閉色盤。
- 一次連續選色共用一筆復原；只打開色盤不會新增復原紀錄。保留只送出 `change` 的瀏覽器回退路徑。
- 換物件、換頁、鎖定、復原後，舊色盤延遲回傳的事件不能修改新的目標。
- 顏色直接寫入原物件模型；沿用 SKC 儲存、原生 PPT 漸層與既有匯出流程，沒有點陣化。

## 效能改動

- SVG 依物件／繪製層保留節點；未變的物件不重建。單純調色只重算目標物件的繪製內容，不重算其他物件的曲線、錨點或圖層清單。
- 保留共用邊界的覆蓋合成。透明度、隱藏、刪除造成分區改變時重新分組，不用錯誤的舊合成。
- 圖頁按鈕與縮圖保留未變內容；背景色即時更新畫布，縮圖在操作暫停後更新。
- 圖層清單只在名稱、順序、分組、選取、顯示或鎖定狀態變動時重建。

2026-09-12，同一 Windows／Chrome 主機的隔離測試：1,800 條簡單線段、移動其中一條後同步更新畫面（8 次取中位數），v95 約 **101.3 ms**，v96 開發期間約 **16–21 ms**。展開 1,800 列圖層時，圖層更新本身由約 **13.7 ms** 降至 **1.8 ms**。這是合成場景測量，不代表複雜曲線、首次載入或所有裝置都能保持固定幀率；舊版的色盤 `input` 根本未更新顏色，不能把它的耗時拿來當等效調色基準。

## 重現與回歸

先啟動測試用靜態伺服器，設定 `SKECHU_TEST_URL`（預設 localhost:18782）及可解析 Playwright 的 `NODE_PATH`：

```text
node tests/measure_editor_render.mjs result-name
node tests/check_live_color_browser.mjs
node tests/check_editor_render_browser.mjs
```

設 `SKECHU_BENCH_EXPANDED=1` 可測展開圖層。量測 JSON 留在忽略追蹤的 `.codex-tmp/color-perf/`。

新增回歸涵蓋 1440px／390px 選色事件、一次復原／重做、未變節點保留、舊事件隔離、150 組多根節點與排序拓撲比對、分區透明度切換，以及增量繪製與原完整 SVG 的逐像素相同比對。測試只使用隔離的合成圖稿，不操作使用者原檔或系統剪貼簿。
